# Plugin Center UI 优化设计

## 目标

将 Snap Plugin Marketing 的插件发现页改成更紧凑的列表界面，减少重复标题、详情内容和卡片信息，让用户能快速搜索、查看仓库、安装插件，并在安装后看到明确状态。

## 范围

- 仅调整 Plugin Center Client 的展示结构与交互。
- 复用现有 Manifest、安装 Remote、已安装状态和 `placement` 元数据。
- 不新增 Host/Remote 接口，不改变插件安装命令和 Harness 生命周期。
- 保留现有卸载 Host 能力，但本次列表界面不暴露卸载操作。

## 页面结构

页面内不再重复显示 `Snap Plugin Marketing` 标题，保留一行发现文案：`发现 DeepSeek Harness 生态插件`。

搜索区域为单行布局：左侧显示发现文案与小号总数量，右侧显示搜索输入框和其右侧的搜索按钮。搜索输入使用草稿值，只有点击搜索按钮或按 Enter 后才提交搜索；提交搜索后分页回到第 1 页。

移除分类导航、图标、作者、标签、详情展开区和当前页面内的详情预览。

## 插件列表行

每个插件占一行，显示：

- 插件名称；
- Manifest 的简短描述；
- 版本与插件类型；
- 当前安装状态；
- `查看` 与 `安装` 两个操作。

`查看` 使用插件的 `repository` 链接在新窗口打开。未安装插件显示可用的 `安装` 按钮；安装成功且重新加载快照后显示禁用的 `已安装` 状态，不再显示卸载按钮。安装中显示忙碌状态，失败消息仍显示在对应行内。

已安装且为 UI 插件时，使用 Manifest 的 `placement` 元数据显示 slot 能力：声明了 `placement.enabled` 和 `slots` 时显示支持的 slot 名称；未声明时显示 `未声明 slot 摆放能力`。能力插件不显示 slot 信息。

## 搜索与分页

搜索沿用现有 `filterPlugins`，匹配插件名称、描述、长描述和标签。过滤后的结果在客户端分页，默认每页 10 条。分页控件只在结果超过一页时出现，显示上一页、页码、下一页；搜索、重新加载和安装成功后的刷新都会将当前页重置为第 1 页。

总数量表示当前搜索结果数量，不是当前页数量。无匹配结果时显示现有空状态。

## 组件与数据流

`PluginCenterTab` 继续负责加载快照、提交搜索、分页、安装状态和错误消息。`PluginCard` 保留组件名以减少接口变更，但改为无详情状态的列表行；它接收现有插件元数据与安装回调，并根据 `installed` 和 `plugin.placement` 渲染状态。

安装仍调用现有 `install(pluginId)`，成功后刷新快照，使用快照中的 `installed` 集合决定是否显示 `已安装`。不根据本地点击乐观声称安装完成。

## 验证

客户端测试覆盖：不重复渲染页面标题、搜索按钮提交、单行列表与仓库链接、安装后已安装状态、已安装 UI 插件的 slot 展示、分页与页码切换，以及空结果状态。随后运行现有客户端测试与 TypeScript 检查；不做真实 Harness 安装或外部仓库验证。
